    Capabilities and executable examples¶

    op_engine is a framework-independent numerical core for structured deterministic and stochastic dynamics, including PDEs, nonlocal interactions, compartmental models, ODEs and reaction networks. NumPy is the core dependency. The separate GPL flepimop2-op_engine package adapts it to flepimop2 and shares its version.

    Model classes and numerical representations¶

    Model class Numerical interface and example Boundary
    Spatial / trait-structured PDEs CoreSolver, grid geometry and diffusion/advection operators; chemostat PDE and biogeochemical splitting Spatial/grid error and time-integration error require separate evidence
    Nonlocal / integro-differential dynamics Matrix/kernel operators and stage operator factories; the provider assembles axis_kernel and jump_integral descriptors Coordinate measures, quadrature, orientation and boundary semantics must agree with the producer
    ODEs and compartmental flows Explicit/IMEX/implicit CoreSolver methods; getting started Method, tolerance and backend qualification are specific to the numerical path
    Stochastic reaction networks Direct/thinning SSA, fixed/adaptive tau-leaping and independent-clock banks; reaction guide Propensities and stoichiometry define event semantics; frozen hazards, thinning bounds and leap approximations have distinct contracts

    Finite array state and an RHS callback are numerical representations used by multiple model classes. The scalar and SIR quickstarts illustrate one entry point; the PDE and nonlocal examples retain their field/operator structure. Provider integration additionally supports configured hybrid partitions; see the provider's hybrid contract for its scope and restrictions.

    Choose a public interface¶

    Task Implemented interface Guide and boundary
    Store state and output times ModelCore Getting started; state is (species, batch) and stored history adds a leading time dimension.
    Solve deterministic dynamics CoreSolver.run Solver methods: explicit, IMEX and linearly implicit methods; select an accuracy policy for the problem.
    Solve nonlinear stages NonlinearProblem, DenseNewtonSolver, NewtonConfig Nonlinear solvers; inspect convergence evidence.
    Integrate stiff or spatial models matrix/operator utilities, GridGeometry, diffusion/advection builders Chemostat, biogeochemistry and linear multistep.
    Simulate a reaction process DirectSSASolver, TauLeapingSolver, AdaptiveTauLeapingSolver Compiled reactions; direct SSA has a superposed clock, tau-leaping is approximate.
    Simulate independent replicate banks BatchedDirectSSASolver, BatchedSSAConfig, from_compiled_replicates Independent SSA; eager NumPy CPU, certified local channels and one clock per replicate.
    Handle smooth time-varying hazards ThinningSSASolver, TotalRateBound Bounded thinning; exactness requires a valid bound throughout its declared interval.
    Record accepted channel firings FiringRecorder Ordinary, thinning, tau and independent-bank solvers; counts do not consume randomness.
    Replay stochastic experiments RandomStream, solver rng and stable replicate IDs Random streams; distinguish reproducibility within a supported runtime from cross-version bitwise identity.
    Evaluate observations and summaries ObservationSpec, observe_model, observe_solution, reduce_observations Named observations; explicit measures, interval/point semantics and storage choices.
    Inspect equilibria and conservation steady_state, conserved_quantities, linear_invariants, sink_states Steady states; convergence and conditional structural identities are separate checks.
    Reuse an adaptive time-step schedule AdaptiveScheduleProvenance, replay controls Replay provenance; validate accuracy away from the producing parameters.

    The backend matrix states which NumPy/JAX/CPU Torch operations and transforms are qualified. Native adaptive solvers such as diffrax live behind optional adapters/providers. Method availability does not imply all methods, stochastic gradients or accelerator paths have the same tested support.

    Run an independent-clock example¶

    uv sync --dev
just example-replicates
just doctest

    examples/replicate_ssa.py uses only the NumPy core. Two S-to-I populations have independent clocks and a shared declared forcing jump at time 1. The script checks total population, accepted firings and exact path replay under bank reordering and singleton runs. Stable IDs define the streams; bank position does not.

    For specification-driven wiring, use the complete example in independent SSA banks, requiring op-system>=0.8.0. A compiler independence certificate is required; a plausible array shape alone cannot prove that two processes are independent. Held rates can use breakpoint SSA. Continuously changing rates require a suitable method such as thinning.

    What runs automatically¶

    Plain pytest and just pytest-core execute library doctests. just doctest also exercises the actual README/getting-started code and the standalone bank. Examples check analytic decay, conserved totals and reproducible paths rather than treating successful execution as numerical evidence. just ci includes these and the core/provider tests, lint, strict typing and citation checks.

    Public docstrings cover state storage, deterministic integration, firing counts, independent clocks and steady-state analysis. Larger spatial tutorials remain covered by their dedicated regression tests. When editing an API, keep its complete example executable and assert an independent reference or invariant. Before a PR, run just ci, just docs, just qualify and just build-all as specified in Contributing.
